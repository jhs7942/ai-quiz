# Llama 파인튜닝 로드맵 (AI Quiz 데이터 활용)

## 현재 데이터 자산 요약

| 데이터 | 규모 | 활용 가치 |
|--------|------|----------|
| 퀴즈 문제 JSON | 12카테고리, ~1,160문제 (question + answer + explanation + difficulty) | **핵심** — instruction 데이터셋의 기반 |
| quiz_answers | 73,848건 (quiz_id, question_id, user_answer, is_correct) | **높음** — 난이도 캘리브레이션, 오답 패턴 |
| quiz_sessions | 4,795건 (categories, score_percent, settings) | **중간** — 사용자 수준별 문제 추천 |
| feedbacks | 134건 (report_type, description, suggested_answer) | **높음** — 문제 품질 개선 시그널 |
| access_logs | 21,428건 | **낮음** — 파인튜닝에는 직접 활용 어려움 |

## Phase 1: 데이터 정제 및 instruction 데이터셋 구축 (2~3주)

### 1-1. 퀴즈 JSON → instruction 포맷 변환

각 문제를 Llama instruction tuning 형식으로 변환:

```jsonl
{
  "instruction": "다음 AI 퀴즈 문제를 만들어주세요. 카테고리: CNN & 이미지 모델, 난이도: medium, 유형: multiple_choice",
  "output": "문제: 합성곱 연산에서 커널 크기가 3x3이고...\n선택지: [\"A\", \"B\", \"C\", \"D\"]\n정답: A\n해설: ..."
}
```

```jsonl
{
  "instruction": "다음 문제에 대한 사용자의 주관식 답변이 맞는지 평가해주세요.\n문제: 모델이 훈련 데이터에만 잘 맞는 현상은?\n정답: 과적합(Overfitting)\n사용자 답변: 오버피팅",
  "output": "정답입니다. '오버피팅'은 'Overfitting'의 한글 표기로, 과적합과 같은 의미입니다."
}
```

### 1-2. 오답 데이터 노이즈 제거

현재 주관식 오답 중 상당수가 의미없는 입력 (`ㅇ`, `.`, `ㅁㄴㅇㄹ`, `gkrtmq` 등). 필터링 기준:
- 2글자 미만 → 제거
- 한글 자음/모음만 → 제거
- 영문 키보드로 한글 입력한 것 (`gkrtmq` = 하는거) → 제거
- **의미있는 오답만 남기기** (예: `머신러닝`, `코사인`, `self-attention` 등)

필터링 후 약 **8,000~12,000건의 유의미한 오답 데이터** 확보 예상.

### 1-3. 피드백 데이터 반영

134건의 피드백에서:
- `wrong_answer` (51건): 정답이 잘못된 문제 → 수정 후 데이터셋에 반영
- `option_error` (14건): 띄어쓰기 등 → 정답 변형(synonym) 리스트 확장
- `ambiguous` (24건): 모호한 문제 → 제거 또는 재작성

## Phase 2: 파인튜닝 목표 설정 (1주)

### 추천 파인튜닝 태스크 (우선순위 순)

| 우선순위 | 태스크 | 설명 | 필요 데이터 |
|---------|--------|------|------------|
| 1 | **문제 생성** | 카테고리+난이도 지정 시 새 문제 자동 생성 | 퀴즈 JSON ~1,160건 |
| 2 | **유연한 채점** | 주관식 답변의 정오답 판정 (동의어, 띄어쓰기, 영한 혼용 허용) | 유의미 오답 ~10,000건 + 정답 쌍 |
| 3 | **해설 생성** | 문제+정답만 주면 해설 자동 생성 | 기존 explanation 1,160건 |
| 4 | **난이도 예측** | 문제 텍스트로 실제 체감 난이도 예측 | 문제별 정답률 통계 |

## Phase 3: 모델 선택 및 파인튜닝 (2~4주)

### 모델 추천

| 모델 | 파라미터 | 추천 이유 |
|------|---------|----------|
| **Llama 3.1 8B** | 8B | 1,160문제 규모에 적합, 단일 GPU(A100/H100 1장)로 QLoRA 가능 |
| Llama 3.1 70B | 70B | 데이터가 더 쌓이면 고려, 현재 규모에는 오버킬 |

### 한국어 특화 대안 모델

- `beomi/Llama-3-Open-Ko-8B` — 한국어 튜닝된 Llama 기반
- **SOLAR 10.7B** (업스테이지) — 한국어 강점
- **Qwen2.5 7B** — 다국어 성능 우수

### 파인튜닝 설정

- **방법**: QLoRA (4-bit quantization + LoRA) — 메모리 효율적, VRAM 24GB면 충분
- **LoRA rank**: 16~64 (데이터 규모가 작으므로 낮은 rank부터 시작)
- **epoch**: 3~5 (과적합 주의)
- **learning rate**: 2e-4 → 1e-5 cosine decay

## Phase 4: 평가 및 서비스 통합 (2~3주)

### 평가 지표

- **문제 생성**: 사람 평가 (fluency, correctness, difficulty 적절성)
- **유연한 채점**: 기존 오답 데이터에서 holdout set으로 precision/recall 측정
- **해설 생성**: ROUGE + 사람 평가

### 서비스 배포 옵션

- vLLM + RunPod/Lambda 등 GPU 서버 (월 $50~200)
- GGUF 양자화 후 로컬 서빙
- Together AI / Fireworks 같은 서빙 플랫폼에 커스텀 모델 업로드

## 데이터 활용 방향별 상세

### 1. 카테고리별 정답률 격차 활용

```
ai-ml-dl-basics:   50.1% (가장 어려움, 347문제)
generative-models: 85.3% (가장 쉬움, 23문제)
```

- **실제 정답률 기반 난이도 재보정** — JSON의 `difficulty` 필드가 아닌, 실측 정답률로 easy/medium/hard를 재분류
- 파인튜닝 시 `"이 문제의 실제 정답률은 50%입니다"` 같은 메타데이터를 포함하면 난이도 인식 정확도 향상

### 2. 주관식 오답 → 동의어 사전 자동 구축

현재 주관식 정답률 40.7%인데, 실제로 맞는데 표기가 달라 틀린 케이스가 많음:
- `과적합` ↔ `오버피팅` ↔ `Overfitting` ↔ `over fitting`
- `손실 함수` ↔ `손실함수` ↔ `loss function`

이 동의어 사전이 태스크 2번(유연한 채점)의 핵심 학습 데이터가 됨.

### 3. 객관식 vs 주관식 비율 최적화

현재: 객관식 65.6%, 주관식 34.4%
→ 파인튜닝된 모델이 주관식 채점을 잘 하게 되면, **주관식 비율을 높여서 학습 효과를 극대화** 가능

## 주의사항

1. **데이터 규모가 작다** — 1,160문제는 LLM 파인튜닝 기준으로 소량. data augmentation 필수:
   - GPT-4o/Claude로 기존 문제를 패러프레이징하여 3~5배 증폭
   - 같은 개념, 다른 문맥의 변형 문제 생성
   - 목표: instruction 데이터 **5,000건 이상**

2. **한국어 특화** — Llama는 영어 중심이므로, 한국어 성능이 좋은 베이스 모델 위에 추가 파인튜닝 권장

3. **점진적 접근** — 처음부터 전체를 만들지 말고:
   - **Step 1**: 유연한 채점만 먼저 (가장 즉각적인 사용자 경험 개선)
   - **Step 2**: 문제 생성 (콘텐츠 확장)
   - **Step 3**: 개인화 추천 (충분한 사용자 데이터 축적 후)
