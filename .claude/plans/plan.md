## 학습용 코드 주석 추가 — quiz flow (2026-05-01)

### 목적
사용자(리액트 학습자)가 핵심 코드 흐름을 따라가도록 `src/store/quizStore.ts`와 `src/pages/QuizPage.tsx`에 **학습용 주석**을 추가한다. 동작 변경 없음 — PR 워크플로우 연습 + 코드 이해를 동시에 수행하기 위한 작업.

### 작업 범위
- `src/store/quizStore.ts` — Zustand 스토어 구조, `set/get` 사용, persist 미들웨어, store 간 참조 (`useWrongNoteStore.getState()`), 정답 정규화 로직
- `src/pages/QuizPage.tsx` — 함수형 컴포넌트의 hook 흐름(`useState/useRef/useEffect`), early return과 hook 규칙, 의존성 배열, 키보드 이벤트 cleanup, 모의고사/일반 모드 분기

### 주석 규칙
- 각 파일에 핵심 학습 포인트 5~8개만 추가 (과도한 주석으로 코드를 더럽히지 않음).
- 주석 형식: `// [학습] {왜 이렇게 짰는지}` — 무엇을 하는지가 아니라 **왜·언제 사용하는 패턴인지**만 적는다.
- 기존 주석은 그대로 유지.
- 코드 로직은 **단 한 줄도 변경하지 않는다**.

### 워크플로우
1. `docs/learn-quiz-flow` 브랜치 생성
2. 두 파일에 학습용 주석 추가
3. `npm run lint` + `npm run build` 로 빌드/린트 통과 확인
4. 한국어 커밋 메시지로 커밋
5. origin push + `gh pr create` 로 PR 생성
6. PR 본문에 ① 학습 포인트 목록 ② 리뷰 시 봐야 할 라인 ③ 사전 지식(Zustand store 패턴, React hook 규칙) 명시

### 검증 지표
> 측정 인프라 미구축 — 학습 목적 작업이므로 정성 기록만. 빌드 통과 + 사용자 PR 승인이 검증 기준.

### 테스트 케이스
> 본 작업은 코드 로직 변경 없음(주석만 추가) — 동작 검증 불요, 테스트 케이스 면제. 단 `npm run build`로 TS 컴파일·Vite 빌드 통과 확인은 진행한다.

### 사전 학습 필요 항목

## Service Worker (PWA) 구현 (2026-04-04)

### 목표
트래픽 몰림 대응 — 재방문 사용자는 서버 요청 없이 캐시에서 앱을 로드.

### 구현 방식
`vite-plugin-pwa` 사용 (Vite 공식 PWA 플러그인, 내부적으로 Workbox 사용).
Service Worker 파일은 빌드 시 자동 생성되므로 직접 작성하지 않음.

### 캐싱 전략

| 대상 | 전략 | 이유 |
|------|------|------|
| JS/CSS/HTML (앱 코어) | **Cache First** | 빌드 해시로 버전 관리 → 항상 캐시 우선 |
| 퀴즈 JSON (`/quizzes/**/*.json`) | **Stale While Revalidate** | 캐시로 즉시 응답 + 백그라운드에서 업데이트 확인 |
| Supabase API 요청 | **Network Only** | 로그/분석은 항상 서버로 전송 필요 |

### 변경 파일

| 파일 | 변경 내용 |
|------|-----------|
| `ai-quiz/package.json` | `vite-plugin-pwa` devDependency 추가 |
| `ai-quiz/vite.config.ts` | VitePWA 플러그인 추가 및 설정 |

`sw.js`는 빌드 시 자동 생성됨 — 직접 작성 파일 없음.

### 기대 효과
- 재방문 시 퀴즈 JSON 서버 요청 0건 (캐시 응답)
- 오프라인 상태에서도 앱 실행 가능
- 동시 접속자 증가 시 서버 부담 감소

## Google AdSense 승인 대응 (2026-03-28)

### 반려 사유
"게시자 콘텐츠가 없는 화면에 Google 게재 광고" — SPA CSR 구조로 인해 크롤러가 빈 페이지로 인식

### 목표
1. **Prerender 적용**: 정적 페이지(/, /about, /contact, /privacy, /report)를 빌드 시 HTML로 미리 생성해 크롤러에 콘텐츠 노출

### 비기능 요구사항
- 사용자 화면 동작 변화 없음 (prerender 후 React hydrate로 동일 동작 유지)
- /quiz, /result 이외 페이지의 광고는 유지

## 프로젝트 개요

Google NotebookLM의 퀴즈 기능에서 영감을 받은 **AI 기반 퀴즈 생성 웹사이트**.
사용자가 파일을 업로드할 필요 없이, LLM API 키만 입력하면 **미리 내장된 참고자료**를 바탕으로 자동으로 퀴즈를 생성하고 풀 수 있다.

## 핵심 기능

### 1. API 키 관리

- 지원 LLM: **Gemini (Google)**, **GPT (OpenAI)**, **Claude (Anthropic)**
- 첫 접속 시 API 키 입력 모달 표시
- 사용자가 **최소 1개** 이상 입력하면 서비스 활성화
- API 키 흐름: 브라우저 → Next.js API Route → LLM 제공사 (서버에 저장하지 않음)
- 브라우저 localStorage에 API 키 암호화 저장
- 설정 패널에서 키 변경·삭제·유효성 테스트 가능
- 입력된 키에 따라 사용 가능한 LLM 목록 자동 업데이트

### 2. 참고자료 탐색 (좌측 사이드바)

NotebookLM의 소스 패널을 응용:

- 내장된 참고자료를 **카드 목록** 형태로 좌측 사이드바에 표시
- 각 자료에 **주제 아이콘** + 간략 설명 표시
- 자료 클릭 시 **내용 요약 미리보기** 패널 확장
- **체크박스로 복수 선택** → 선택한 자료 기반 퀴즈 생성
- AI_상세정리.html의 경우 **14개 세부 토픽** 펼쳐서 개별 선택 가능:
  - AI 계층 구조, ANN 발전, 학습 파이프라인, 활성화·손실 함수, 옵티마이저,
    규제, CNN, 이미지 모델 변천사, RNN & LSTM, 전이 학습,
    ML 학습 종류, 학습 고려사항, 데이터 처리, 파운데이션·생성 모델
- 전체 선택 / 해제 토글

### 3. 퀴즈 생성

NotebookLM의 퀴즈 생성 방식을 참고:

- **퀴즈 옵션 설정 패널** (메인 영역에 카드 형태로 표시):
  - 문제 유형: 객관식(4지선다) / OX(참·거짓) / 단답형 / 혼합
  - 난이도: 쉬움 / 보통 / 어려움
  - 문제 수: 5 / 10 / 15 / 20
  - 사용할 LLM 선택 (입력된 API 키 중 택 1)
- 선택한 참고자료의 **텍스트를 추출**하여 LLM에 프롬프트와 함께 전달
- LLM이 **구조화된 JSON**으로 퀴즈 반환 (문제, 보기, 정답, 해설, 출처)
- 생성 중 **스켈레톤 로딩** + 진행 메시지 표시
- 참고자료 크기가 클 경우 자동 분할(청킹) 처리

### 4. 퀴즈 풀기 (메인 기능)

NotebookLM 퀴즈 UI를 참고한 인터랙티브 퀴즈 화면:

- **한 문제씩** 카드 형태로 표시
- 상단 **프로그레스 바** + 문제 번호 (예: 3 / 10)
- 문제 유형별 인터랙션:
  - **객관식**: 보기 4개를 카드형 버튼으로 표시, 클릭 선택
  - **OX**: O / X 큰 버튼 2개
  - **단답형**: 텍스트 입력 필드 + 제출 버튼
- **즉시 피드백**:
  - 정답 → 초록 하이라이트 + 체크 아이콘 + 해설 카드 펼침
  - 오답 → 빨강 하이라이트 + X 아이콘 + 정답 표시 + 해설 카드 펼침
  - 해설에 **출처 태그** 표시 (어느 참고자료의 어떤 부분에서 출제)
- 하단 네비게이션: [이전] [건너뛰기] [다음]
- 사이드에 **문제 번호 네비게이터** (클릭으로 특정 문제 이동, 풀린/안풀린 표시)

### 5. 결과 화면

- **도넛 차트**로 정답률 시각화
- 점수 표시 (예: 8 / 10 — 80%)
- **탭 분류**: 전체 / 맞은 문제 / 틀린 문제
- 각 문제 카드: 내 답변 vs 정답 비교 + 해설 + 출처
- 하단 액션 버튼:
  - [오답만 다시 풀기] — 틀린 문제로 새 퀴즈
  - [같은 문제 다시 풀기] — 문제 순서 셔플
  - [새 퀴즈 생성] — 설정 화면으로 돌아가기
- 결과 요약 텍스트 **클립보드 복사** (공유용)

### 6. 퀴즈 히스토리 (Nice-to-have)

- localStorage에 이전 퀴즈 결과 저장
- 메인 화면에서 "최근 퀴즈" 목록 표시
- 과거 퀴즈 다시 풀기 가능
- 시간별 성적 추이 간단 그래프

### 7. 오답 노트 (Nice-to-have)

- 틀린 문제를 자동 수집
- 오답 노트에서 "오답 복습 퀴즈 생성" 버튼
- 주제별 취약 영역 표시

## 사용자 흐름 (User Flow)

```
[접속]
  │
  ├─ API 키 미입력 → 풀스크린 온보딩 페이지
  │   ├─ 서비스 소개 + 지원 LLM 안내
  │   ├─ Gemini / GPT / Claude API 키 입력 (최소 1개)
  │   ├─ [키 유효성 테스트] 버튼
  │   └─ [시작하기] → 메인 화면
  │
  └─ API 키 있음 → [메인 화면]

  ├─ 좌측 사이드바
```

## 제약사항 및 비기능 요구사항

- **API 키 보안**: API 키는 localStorage에 저장, API Route를 경유하여 LLM 호출 (서버에 영구 저장 안 함)
- **참고자료 내장**: HTML에서 텍스트 추출 후 빌드 시 JSON으로 변환하여 포함
- **토큰 관리**: 참고자료가 길 경우 자동 분할(청킹)하여 LLM 컨텍스트 제한 내 처리
- **LLM 호환**: Gemini, OpenAI GPT, Anthropic Claude 3종 모두 동일 프롬프트 구조로 지원
- **에러 처리**: API 키 오류, 요청 실패, 타임아웃 시 사용자 친화적 메시지 + 재시도 버튼
- **반응형**: 3단계 브레이크포인트 대응
  - 데스크톱 (≥ 1024px): 사이드바 고정, 문제 번호 네비게이터 우측 표시
  - 태블릿 (640px ~ 1023px): 사이드바 드로어, 네비게이터 카드 하단 인라인 표시
  - 모바일 (< 640px): 사이드바 드로어, 네비게이터 하단 고정, 버튼/패딩 크기 축소
- **터치 최적화**: 모바일에서 탭 타겟 최소 44px 이상, 스와이프 고려
- **브라우저**: 최신 Chrome / Safari / Firefox / Edge (iOS Safari · Android Chrome 포함)
