# JSON 기반 퀴즈 웹사이트 — 요구사항 정리 (plan2.md)

## 프로젝트 개요

Google NotebookLM의 퀴즈 기능에서 영감을 받은 **JSON 기반 퀴즈 웹사이트**.
사용자는 미리 제작된 JSON 퀴즈 파일의 문제를 웹에서 풀고, 즉시 피드백을 받는다.
LLM API 없이, **사전 제작된 퀴즈 데이터**만으로 동작한다.

| 피드백 | 없음 | **문제 오류 신고** 기능 추가 |

## 핵심 기능

### 1. JSON 퀴즈 데이터 관리

- 퀴즈 데이터는 **JSON 파일**로 사전 제작하여 프로젝트에 포함
- **객관식(4지선다)**과 **주관식** 문제를 같은 파일에 혼합 구성 가능
- JSON 파일 구조 — `type` 필드로 문제 유형 구분:
  ```json
  [
    {
      "id": 1,
      "type": "multiple_choice",
      "difficulty": "easy",
      "question": "다음 중 인공지능(AI), 머신러닝(ML), 딥러닝(DL)의 포함 관계로 올바른 것은?",
      "choices": ["AI ⊃ ML ⊃ DL", "ML ⊃ AI ⊃ DL", "DL ⊃ ML ⊃ AI", "AI ⊃ DL ⊃ ML"],
      "answer": "AI ⊃ ML ⊃ DL",
      "explanation": "AI는 인간 지능을 모방하는 기술 전체를 의미하며, ML은 데이터를 학습하는 방법론, DL은 다층 신경망을 사용하는 ML의 하위 분야입니다."
    },
    {
      "id": 2,
      "type": "short_answer",
      "difficulty": "easy",
      "question": "데이터를 분석 전에 여러 각도에서 관찰하고 이해하는 과정을 무엇이라 합니까?",
      "answer": "탐색적 데이터 분석(EDA)",
      "explanation": "EDA는 시각화, 통계 요약 등을 통해 데이터의 특성을 파악하는 과정입니다."
    }
  ]
  ```
- **필드 설명**:
  - `id`: 문제 번호 (정수)
  - `type`: 문제 유형 — `"multiple_choice"` (객관식) | `"short_answer"` (주관식)
  - `difficulty`: 난이도 — `"easy"` | `"medium"` | `"hard"`
  - `question`: 문제 텍스트
  - `choices`: 보기 4개 (문자열 배열, **`multiple_choice`일 때만 포함**)
  - `answer`: 정답 텍스트 (객관식은 choices 중 하나와 일치)
  - `explanation`: 해설
- 카테고리별로 JSON 파일 분리 (예: `ai-basics.json`, `numpy-pandas.json`, `cnn-attention.json` 등)
- 새 퀴즈 추가 시 JSON 파일 추가 + `index.json` 등록으로 자동 반영
- **`index.json` 구조** — 카테고리 메타데이터 관리:
  ```json
  {
    "categories": [
      {
        "id": "ai-basics",
        "title": "AI 기초",
        "description": "인공지능, 머신러닝, 딥러닝의 기본 개념",
        "icon": "brain",
        "file": "ai-basics.json"
      }
    ]
  }
  ```

### 2. 퀴즈 카테고리 선택 (좌측 사이드바)

NotebookLM의 소스 패널을 응용:

- JSON 파일 기반 퀴즈 목록을 **카드 형태**로 좌측 사이드바에 표시
- 각 카테고리에 **아이콘 + 제목 + 문제 수 + 설명** 표시
- 카테고리 클릭 시 해당 퀴즈의 **미리보기** (문제 수, 난이도 분포) 표시
- **체크박스로 복수 선택** → 선택한 카테고리의 문제를 합쳐서 퀴즈 구성 가능
- 전체 선택 / 해제 토글

### 3. 퀴즈 설정

- **퀴즈 옵션 설정 패널** (메인 영역에 카드 형태로 표시):
  - 난이도 필터: 쉬움 / 보통 / 어려움 / 전체
  - 문제 수: 5 / 10 / 15 / 20 / 전체
  - 문제 순서: 순서대로 / 랜덤 셔플
- 선택한 카테고리 + 난이도 조건에 맞는 문제를 추출하여 퀴즈 구성
- **유형별 균등 배분**: 객관식·주관식이 혼합된 경우, 전체 문제의 유형 비율에 맞게 균등 배분
  - 예: 전체 문제가 객관식 60개 + 주관식 40개이고 10문제 요청 시 → 객관식 6개 + 주관식 4개
- 조건에 맞는 문제가 부족할 경우 안내 메시지 표시

### 4. 퀴즈 풀기 (메인 기능)

NotebookLM 퀴즈 UI를 참고한 인터랙티브 퀴즈 화면:

- **한 문제씩** 카드 형태로 표시
- 상단 **프로그레스 바** + 문제 번호 (예: 3 / 10)
- **문제 유형에 따른 입력 방식** (유형 라벨은 UI에 표시하지 않음):
  - 객관식: 보기 4개를 카드형 버튼으로 표시, 클릭으로 선택 (선택만 — 즉시 채점하지 않음)
  - 주관식: 텍스트 입력창 표시, 답변 입력 (입력만 — 즉시 채점하지 않음)
- **주관식 채점 기준**: 사용자 입력이 `answer` 필드에 **포함**되어 있으면 정답으로 인정
  - 예: answer가 "탐색적 데이터 분석(EDA)"일 때 → "EDA", "탐색적 데이터 분석", "탐색적 데이터 분석(EDA)" 모두 정답
- **정답 확인 / 다음 버튼 분리**:
  - [정답 확인]: 답변을 선택/입력한 뒤 클릭하면 채점 + 피드백 표시. 답변 미선택 시 비활성화
  - [다음]: 정답 확인 후 활성화되어 다음 문제로 이동. 정답 확인 전에는 비활성화
- **피드백** (정답 확인 클릭 시):
  - 정답 → 초록 하이라이트 + 체크 아이콘 + 해설 카드 펼침
  - 오답 → 빨강 하이라이트 + X 아이콘 + 정답 표시 + 해설 카드 펼침
- 하단 네비게이션: [이전] [건너뛰기] [정답 확인] [다음]
  - **이전**: 이전 문제로 이동. 이미 채점된 문제도 **답변 수정 가능** (수정 시 채점 결과 초기화 → 다시 [정답 확인] 필요)
  - **건너뛰기**: 현재 문제를 미완료 상태로 두고 다음 문제로 이동, 문제 번호 네비게이터에서 미완료(⬡) 표시로 구분되어 언제든 클릭하여 돌아올 수 있음
  - **정답 확인**: 답변 선택/입력 후 클릭 시 채점 및 피드백 표시
  - **다음**: 정답 확인 완료 후 다음 문제로 이동
- **미풀이 문제 안내**: 마지막 문제에서 [결과 보기] 클릭 시, 건너뛴 문제가 남아있으면 팝업 표시
  - "아직 풀지 않은 문제가 있어요" + 미풀이 문제 수 표시
  - [문제 풀러 가기]: 첫 번째 미풀이 문제로 이동
  - [제출]: 미풀이 문제를 남긴 채 결과 화면으로 이동
- **나가기 버튼**: 상단 [나가기] 클릭 시 확인 팝업 표시
  - "퀴즈를 나가시겠습니까? 진행 상황이 사라집니다."
  - [계속 풀기] / [나가기] 버튼
  - 나가기 확인 시 메인 화면(`/`)으로 이동, **DB에 저장하지 않음** (중도 이탈 데이터 미수집)
- 사이드에 **문제 번호 네비게이터** (클릭으로 특정 문제 이동, 풀린 ● / 건너뜀 ⬡ / 안풀린 ○ 구분 표시)
- **문제 오류 신고 버튼** (각 문제 카드 우상단): 🚨 신고하기
- **이탈 방지**: 퀴즈 풀기 중 새로고침/뒤로가기 시 경고 팝업 표시
  - `beforeunload` 이벤트 리스너 + React Router `useBlocker`로 브라우저 뒤로가기 차단
  - "퀴즈를 나가시겠습니까? 진행 상황이 사라집니다." 확인 다이얼로그
  - 퀴즈 결과 제출 완료 후에는 리스너 해제

### 5. 문제 오류 신고 기능

- 각 문제 카드에 **[🚨 신고하기]** 버튼 배치
- 클릭 시 **팝업(모달)** 표시:
  - 신고 유형 선택 (라디오 버튼):
    - 정답이 틀림
    - 문제가 모호함
    - 해설이 부정확함
    - 보기에 오류가 있음
    - 기타
  - 상세 내용 입력 (텍스트 영역, 최대 500자)
  - 사용자가 생각하는 올바른 답 입력 (선택)
  - [제출] / [취소] 버튼
- 제출 시 DB에 저장 (별도 `feedbacks` 테이블)
- 제출 완료 후 "신고가 접수되었습니다" 토스트 메시지 표시
- 이미 신고한 문제는 버튼에 "신고됨" 표시 (중복 신고 방지)

### 6. 결과 화면

- **도넛 차트**로 정답률 시각화
- 점수 표시 (예: 8 / 10 — 80%)
- **탭 분류**: 전체 / 맞은 문제 / 틀린 문제 / 건너뛴 문제
  - 건너뛴 문제는 정답/오답 집계에서 제외, 별도 "미풀이" 표시
- 각 문제 카드: 내 답변 vs 정답 비교 + 해설 + 출처
- 하단 액션 버튼:
  - [오답만 다시 풀기] — 틀린 문제로 새 퀴즈
  - [같은 문제 다시 풀기] — 문제 순서 셔플
  - [새 퀴즈 생성] — 설정 화면으로 돌아가기
- 결과 요약 텍스트 **클립보드 복사** (공유용)

### 7. 사용자 통계 및 접속 로그 (DB)

#### 사용자 통계
- 총 사용자 수 (고유 방문자)
- 총 퀴즈 풀이 횟수
- 총 문제 풀이 수
- 카테고리별 풀이 수
- 일별/주별/월별 풀이 통계

#### 접속 로그
- 사용자 접속 시간
- 접속 기기 / 브라우저 정보 (User-Agent)
- 페이지 방문 기록
- 세션 지속 시간

#### 관리자 대시보드 (선택)
- 통계 데이터를 시각화하는 간단한 관리자 페이지
- 신고된 문제 목록 확인 및 처리 상태 관리

## DB 스키마 설계

### 테이블 구조

#### 1. `questions` — 문제 메타데이터
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | VARCHAR (PK) | 문제 고유 ID (JSON 파일 내 id) |
| quiz_id | VARCHAR | 퀴즈 파일 ID (카테고리) |
| type | VARCHAR | 문제 유형 (`multiple_choice` / `short_answer`) |
| difficulty | VARCHAR | 난이도 (`easy` / `medium` / `hard`) |
| created_at | TIMESTAMP | 등록 시간 |

> JSON 파일 배포 시 앱 초기화 과정에서 DB에 upsert하여 동기화

#### 2. `users` — 사용자 (익명 / 세션 기반)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | UUID (PK) | 사용자 고유 ID |
| session_id | VARCHAR | 브라우저 세션 ID |
| first_visit_at | TIMESTAMP | 최초 접속 시간 |
| last_visit_at | TIMESTAMP | 마지막 접속 시간 |
| visit_count | INTEGER | 총 방문 횟수 |
| user_agent | TEXT | 브라우저 정보 |

#### 3. `access_logs` — 접속 로그
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | BIGINT (PK) | 로그 ID |
| user_id | UUID (FK) | 사용자 ID |
| accessed_at | TIMESTAMP | 접속 시간 |
| page_path | VARCHAR | 방문 페이지 경로 |
| user_agent | TEXT | 브라우저 정보 |
| session_duration | INTEGER | 세션 지속 시간 (초) |

#### 4. `quiz_sessions` — 퀴즈 풀이 세션
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | UUID (PK) | 퀴즈 세션 ID |
| user_id | UUID (FK) | 사용자 ID |
| categories | TEXT[] | 선택한 카테고리 목록 |
| total_questions | INTEGER | 총 문제 수 |
| correct_count | INTEGER | 정답 수 |
| score_percent | DECIMAL | 정답률 (%) |
| started_at | TIMESTAMP | 시작 시간 |
| completed_at | TIMESTAMP | 완료 시간 |
| selected_types | TEXT[] | 선택한 문제 유형 목록 (객관식/주관식) |
| settings | JSONB | 퀴즈 설정 (난이도, 셔플 여부 등) |
| pretest | BOOLEAN | 실전 모의고사 여부 (기본값: false) |

#### 5. `quiz_answers` — 개별 문제 풀이 기록
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | BIGINT (PK) | 답변 ID |
| quiz_session_id | UUID (FK) | 퀴즈 세션 ID |
| question_id | VARCHAR | 문제 ID (JSON 내 ID) |
| quiz_id | VARCHAR | 퀴즈 파일 ID |
| user_answer | TEXT | 사용자 답변 |
| is_correct | BOOLEAN | 정답 여부 |
| question_type | VARCHAR | 문제 유형 (`multiple_choice` / `short_answer`) |
| answered_at | TIMESTAMP | 답변 시간 |
| pretest | BOOLEAN | 실전 모의고사 여부 (기본값: false) |

#### 6. `feedbacks` — 문제 오류 신고
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | BIGINT (PK) | 신고 ID |
| user_id | UUID (FK) | 신고자 ID |
| quiz_id | VARCHAR | 퀴즈 파일 ID |
| question_id | VARCHAR | 문제 ID |
| report_type | VARCHAR | 신고 유형 (wrong_answer / ambiguous / bad_explanation / option_error / other) |
| description | TEXT | 상세 내용 (최대 500자) |
| suggested_answer | TEXT | 사용자가 제안하는 올바른 답 (선택) |
| status | VARCHAR | 처리 상태 (pending / reviewed / resolved / rejected) |
| created_at | TIMESTAMP | 신고 시간 |

#### 7. `daily_stats` — 일별 통계 (집계 테이블)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| date | DATE (PK) | 날짜 |
| unique_visitors | INTEGER | 고유 방문자 수 |
| total_quiz_sessions | INTEGER | 총 퀴즈 풀이 횟수 |
| total_questions_answered | INTEGER | 총 문제 풀이 수 |
| avg_score_percent | DECIMAL | 평균 정답률 |

```

  │

[메인 화면]
  ├─ 좌측 사이드바
  │   ├─ 퀴즈 카테고리 카드 목록 (체크박스 선택)

  │   └─ 선택 현황: "3개 카테고리 선택됨 (총 30문제)"
  │
  └─ 우측 메인 영역
       ├─ 선택 없음 → 일러스트 + "좌측에서 퀴즈를 선택하세요" 안내
       │
       └─ 카테고리 선택됨 → 퀴즈 설정 카드
            ├─ 난이도 필터 (칩)
            ├─ 문항 수 (칩: 5/10/15/20/전체)
            ├─ 순서 (순서대로/랜덤)
            └─ [퀴즈 시작하기] 버튼
                 │
                 └─ [퀴즈 화면]

[퀴즈 화면]
  ├─ 상단: 프로그레스 바 + 문제 번호 (3/10) + [나가기]
  │         └─ [나가기] → 확인 팝업 → 메인 화면 이동 (DB 저장 X)
  │
  ├─ 중앙: 문제 카드
  │   ├─ 문제 텍스트
  │   ├─ [객관식] 보기 4개 (카드형 버튼, 선택만) / [주관식] 텍스트 입력창
  │   ├─ [🚨 신고하기] 버튼 (우상단)
  │   ├─ [정답 확인] 클릭 시 채점 (주관식: 입력값이 answer에 포함되면 정답)
  │   └─ 피드백 카드 펼침
  │       ├─ ✓ 정답! or ✗ 오답
  │       └─ 해설
  │
  ├─ 하단: [이전] [건너뛰기] [정답 확인] [다음]
  │         ├─ 이전: 이전 문제로 이동 (답변 수정 가능, 수정 시 채점 초기화)
  │         ├─ 정답 확인: 답변 선택 후 채점 실행 (미선택 시 비활성화)
  │         ├─ 다음: 정답 확인 후 활성화 (확인 전 비활성화)
  │         └─ 건너뛰기: 미완료 상태로 두고 다음 문제로 이동
  │
  ├─ 사이드: 문제 번호 네비게이터 (● 완료 / ⬡ 건너뜀 / ○ 미풀이)
  │
  └─ 진행 상태 sessionStorage 자동 저장 (새로고침해도 유지)

[🚨 신고하기 클릭]
  └─ 팝업(모달) 표시
```

## 제약사항 및 비기능 요구사항

- **퀴즈 데이터**: `/public/quizzes/` JSON 파일로 관리, 새 파일 추가 + `index.json` 등록만으로 자동 반영

- **개인정보**: 최소한의 정보만 수집 (IP 수집 없음)
- **세션 저장**: 퀴즈 풀이 중간 상태를 `sessionStorage`에 저장하여 **새로고침해도 진행 상황 유지**
  - 저장 데이터: 현재 문제 인덱스, 각 문제별 선택한 답변, 채점 결과(정답/오답/미풀이), 퀴즈 설정
  - 저장 시점: 답변 선택/채점/문제 이동 시마다 자동 저장
  - 삭제 시점: 결과 화면 도달 시 또는 나가기 시
- **에러 처리**: DB 연결 실패 시에도 퀴즈 풀기는 가능 (로그/통계만 누락)
- **배포**: 정적 파일(SPA) — Vercel / Netlify / GitHub Pages 어디서든 배포 가능
- **반응형**: 데스크톱 (사이드바 고정) / 태블릿·모바일 (사이드바 드로어)
- **브라우저**: 최신 Chrome / Safari / Firefox / Edge

## 8. 실전 모의고사 기능

### 개요
- 기존 카테고리 퀴즈와 별도로 **"실전 모의고사"** 메뉴를 제공
- `public/quizzes/mock-exams/` 디렉토리에 JSON 파일을 두면, **파일 수 = 풀 수 있는 모의고사 수**로 자동 반영
- 예: JSON 파일 30개 → 모의고사 30회 표시

### 데이터 구조

**모의고사 인덱스**: `public/quizzes/mock-exams/index.json`
```json
[
  {
    "id": "pre_test1",
    "title": "실전 모의고사 1회",
    "description": "전 범위 종합 모의고사",
    "file": "pre_test1.json",
    "questionCount": 50
  },
  {
    "id": "pre_test2",
    "title": "실전 모의고사 2회",
    "description": "전 범위 종합 모의고사",
    "file": "pre_test2.json",
    "questionCount": 50
  }
]
```

**모의고사 문제 파일**: `public/quizzes/mock-exams/pre_test{N}.json`
- `pre_test2.json`과 **동일한 형식** 사용 — 객관식 4지선다 문제 배열
- 각 파일이 하나의 완전한 시험지 — 문제 수, 순서, 난이도 배분이 고정되어 있음
- JSON 구조:
  ```json
  [
    {
      "id": 1,
      "type": "multiple_choice",
      "difficulty": "easy",
      "question": "문제 텍스트",
      "choices": ["보기1", "보기2", "보기3", "보기4"],
      "answer": "정답 보기",
      "explanation": "해설 텍스트"
    }
  ]
  ```

### UI/UX 레이아웃

```
사이드바                 메인 영역
┌───────────────┐  ┌──────────────────────────┐
│ 📋 실전 모의고사 ◀──┤  실전 모의고사             │
│ ─────────────── │  │                          │
│ 📚 퀴즈 카테고리  │  │  ┌────────┐ ┌────────┐  │
│  □ AI/ML/DL 기초│  │  │ 1회    │ │ 2회    │  │
│  □ 활성화함수    │  │  │ 50문제  │ │ 50문제  │  │
│  □ 최적화       │  │  └────────┘ └────────┘  │
│  □ 데이터전처리  │  │  ┌────────┐ ┌────────┐  │
│  □ CNN & 이미지  │  │  │ 3회    │ │ 4회    │  │
│  ...            │  │  │ 50문제  │ │ 50문제  │  │
│                 │  │  └────────┘ └────────┘  │
└───────────────┘  └──────────────────────────┘
```

**사이드바**:
- 기존 카테고리 목록 **위에** "실전 모의고사" 단일 항목 배치
- 클릭 시 가운데 메인 영역에 모의고사 회차 카드 그리드 표시
- 기존 카테고리 체크박스와는 독립적으로 동작

**메인 영역 (모의고사 선택 화면)**:
- 모의고사를 **카드 그리드** 형태로 표시
- 각 카드: 회차 번호 + 문제 수
- 카드 클릭 → 해당 모의고사 **즉시 시작** (별도 시작 버튼 없이 카드 자체가 버튼 역할)

**모의고사 풀이** (실제 시험 모드):
- 기존 QuizPage UI 사용하되, **실제 시험처럼 풀이 중 정답을 보여주지 않음**
- **"정답 확인" 버튼 없음** — 답변 선택 후 바로 "다음" 버튼으로 다음 문제 이동
- 풀이 중 정답/오답 하이라이트, 해설 패널 **미표시**
- 난이도 필터/문항 수 설정/셔플 옵션 없음 — JSON 파일의 문제 전체를 순서대로 출제
- 상단에 "실전 모의고사 N회" 표시
- 모든 문제 완료 후 **결과 페이지 이동 시 일괄 채점**

**모의고사 결과**:
- 기존 ResultPage와 **동일한 UI** 사용
- 결과 화면에서 **정답/오답/해설 최초 공개** (풀이 중에는 볼 수 없었던 정보)
- "실전 모의고사 N회" 타이틀 표시
- 오답 재시험, 같은 문제 다시 풀기 등 기존 기능 그대로 사용 가능

### DB 저장 (모의고사 구분)
- 모의고사 풀이 시 `quiz_sessions.pretest = true`로 저장
- **`quiz_answers` 테이블에는 모의고사 데이터를 저장하지 않음** (세션 요약만 기록)
- 기존 카테고리 퀴즈는 `pretest = false` (기본값), `quiz_answers`에 개별 답변 기록

### 기존 기능과의 분리
- 모의고사는 기존 카테고리 선택 + 설정 흐름과 **독립적**
- 모의고사 선택 시 카테고리 체크박스, 난이도/문항수/셔플 설정을 거치지 않음
- 한 번의 클릭으로 바로 시험 시작

### 확장성
- JSON 파일을 추가하고 `index.json`에 등록하면 자동 반영
- 별도 코드 수정 없이 모의고사 수 무한 확장 가능
