# 시험 이틀 전, 4시간 만에 Claude Code로 AI 퀴즈 앱 만들기

## 학습 환경
- 날짜: 2026-03-24 ~ 2026-04-08 / 관련 프로젝트: AI Quiz / 기술·버전: Vite 8, React 19, Zustand 5, Supabase, Tailwind CSS 4, TypeScript 5

## 배경
AI 과목 시험이 이틀 앞으로 다가온 상황에서, 강의 자료 기반의 퀴즈 학습 도구가 필요했다. 시중 퀴즈 앱은 커스텀 문제를 지원하지 않았고, NotebookLM의 퀴즈 기능에서 영감을 받아 직접 만들기로 결정했다.

제약 조건이 명확했다:
- **시간**: 4시간 이내 완성
- **비용**: Claude Code Pro 요금제 — 토큰 한도 내에서 완성해야 함
- **목적**: 본인의 시험 대비용 (범용 서비스가 아님)
- **코드 작성**: 모든 코드는 Claude Code가 생성, 사람은 요구사항 지시만 담당

## 핵심 개념

### 1. 제약이 강제한 기술 선택

| 결정 | 선택 | 탈락 후보 | 이유 |
|------|------|-----------|------|
| 프레임워크 | Vite + React | Next.js | JSON만 화면에 뿌려주면 됨, SSR 불필요, 빌드 속도 빠름 |
| 퀴즈 데이터 | JSON 사전 제작 | LLM API 동적 생성 | API 비용 0원 + 오프라인 가능 + 4시간 내 완성 가능 |
| UI 구현 | Claude Code 직접 생성 | 디자인/평가 에이전트 | 토큰 절약 — 디자인 에이전트는 토큰 소모가 크므로 생략 |
| 상태관리 | Zustand | Redux | 보일러플레이트 최소, persist 미들웨어로 세션 복구 한 줄 |
| DB | Supabase (분석 전용) | Firebase, 자체 서버 | 퀴즈는 JSON, 통계/로깅만 DB. anon key로 로그인 불필요 |

핵심 판단: **"디자인 완성도 < 기능 완성도"** 트레이드오프를 의식적으로 선택했다. Claude Code에는 UI 프로토타입을 만들고 멀티 페르소나로 평가하는 에이전트가 있지만, 이 과정이 토큰을 많이 소모한다. Pro 요금제 한도 내에서 4시간 만에 완성하려면 이 과정을 생략하고, Claude Code가 Tailwind CSS로 직접 UI를 한 번에 생성하는 방식을 택했다.

### 2. v1 → v2 아키텍처 전환

```
v1 (초기 4시간): Next.js + LLM API 키 입력 → 실시간 퀴즈 생성
  ↓ (문제 발견: API 비용, 응답 속도 불안정, 오프라인 불가)
v2 (현재): Vite + JSON 사전제작 퀴즈 → 정적 배포
```

v1은 "사용자가 API 키를 입력하면 LLM이 강의 자료를 읽고 퀴즈를 생성"하는 구조였다. 하지만 실제로 사용해보니 API 호출 비용, 응답 지연, 문제 품질 불균일 문제가 있었다. v2에서는 직접 JSON으로 문제를 사전 제작하는 방식으로 전환했고, 이것이 오히려 문제 품질·속도·비용 모든 면에서 우월했다.

### 3. "분석 전용 DB" 아키텍처

Supabase를 퀴즈 데이터 저장이 아닌 **분석/로깅 전용**으로만 사용하는 구조:
- 퀴즈 데이터: `public/quizzes/*.json` (정적 파일)
- DB 역할: 사용자 통계, 풀이 기록, 피드백 수집
- 모든 DB 호출은 silent fail — DB 장애 시에도 퀴즈는 정상 동작
- anon key 기반이라 회원가입/로그인 불필요

이 구조 덕분에 Supabase가 다운되어도 퀴즈 기능 자체에는 영향이 없다.

### 4. 이후 확장 과정 (4시간 → 현재)

최초 4시간으로 MVP를 만든 후, 시험 기간과 이후에 걸쳐 점진적으로 기능을 추가했다:

| 시점 | 추가 기능 |
|------|-----------|
| MVP (4시간) | 카테고리 선택, 퀴즈 풀기, 결과 화면 |
| +1일 | 실전 모의고사 모드 (시간 제한, 일괄 채점) |
| +3일 | 다크모드, 오답노트, 키보드 네비게이션 |
| +1주 | Google AdSense 대응 (prerender), SEO 서브페이지 |
| +2주 | 문제별 즉시 저장, Supabase RLS 수정, 모의고사 6회분 추가 |

"만들어놓고 안 쓰는 포트폴리오"가 아니라, 실제 시험 준비에 사용되고 다른 사용자들도 활용한 제품.

### AI 도구 활용 방식

모든 코드(React 컴포넌트, Zustand 스토어, Supabase 연동, Tailwind CSS, TypeScript 타입 등)는 Claude Code가 생성했다. 사람의 역할은:
- 요구사항 정의 (plan.md 작성)
- 기능 우선순위 결정
- 생성된 결과 검증 및 방향 수정
- 퀴즈 문제 데이터 직접 제작

디자인/평가 에이전트를 생략했음에도 Tailwind CSS 기반으로 반응형 3단계(데스크톱/태블릿/모바일), 다크모드, 접근성(키보드 네비게이션)까지 구현되었다.

### 향후 계획: 파인튜닝

축적된 73,848건의 풀이 데이터를 활용하여:
1. 문제 자동 생성 (Llama 파인튜닝)
2. 유연한 주관식 채점 (의미적 유사성 기반)
3. 해설 자동 생성

## 주의사항

### "빠르게 만들기"의 부작용
- 4시간 만에 만들다 보니 배치 저장 로직에 동시성 버그가 있었음 (이후 리뷰 에이전트가 발견)
- PWA + 배치 저장 + RLS 수정을 한꺼번에 배포했다가 원인 분리가 안 되어 `git reset --hard`로 롤백
- **교훈**: 빠르게 만들되, 배포는 기능별로 분리해야 함

### AI 도구 활용의 교훈
- 토큰은 유한한 자원 — "어디에 토큰을 쓸 것인가"라는 자원 배분 판단이 중요
- 디자인 에이전트를 생략해도 Tailwind CSS로 충분히 사용 가능한 UI가 나옴
- 다만 구현 에이전트가 만든 코드를 리뷰 에이전트로 검증하는 단계는 생략하면 안 됨

### 포트폴리오 관점
- 기술 스택의 화려함보다 **"제약 안에서 실사용 제품을 만든 경험"**이 실무에 가깝다
- 성과 지표(사용자 데이터)가 있으면 설득력이 크게 올라감
- AI 도구 활용 과정을 솔직하게 기록하는 것이 오히려 플러스
